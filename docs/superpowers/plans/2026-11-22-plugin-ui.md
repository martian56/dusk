# Plugin UI (Delivery Step 2) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Plugins show UI that dusk draws: pickers, one-line prompts, docked panels made of blocks, and per-line marks; the SDK gains builders for them and a TODO finder example.

**Architecture:** `src/ui.rv` holds the panel model (blocks, scroll, selection, input text) and pure layout of blocks into styled lines; `host.rv` parses the new messages into `HostAction` variants; `editor.rv` owns focus, routes keys and clicks to the focused panel, and answers picks and prompts through the existing picker and prompt modes; `view.rv` reserves space for docked panels and draws marks in the gutter.

**Tech Stack:** Raven 3.3.3, plumage 0.5.2, magpie 0.5.0 (markdown text blocks), dusk-plugin 0.2.0.

**Spec:** `docs/superpowers/specs/2026-11-22-plugin-system-design.md`

## Global Constraints

- Everything in the step 1 plan's Global Constraints still holds.
- F6 moves focus editor, then each panel in order, then back to the editor; Shift+F6 goes the other way; a click focuses what it lands on; Esc in a panel returns focus to the editor. Ctrl+W keeps closing the current file.
- A right-docked panel is `min(60, w * 2 / 5)` columns wide; bottom-docked panels share `min(14, h / 3)` rows. With no panels the layout is exactly as today.
- Block kinds: `text` (markdown via magpie), `list` (rows with optional detail), `input` (multi-line, Enter submits, Alt+Enter inserts a newline), `buttons`, `progress` (label plus spinner, or a bar when `value` 0..100 is given).
- Replacing a panel (`ui/panel` with an existing id) keeps its scroll, its selected row when it still exists, the input text when the new input block has no `text`, and focus.

## Review Focus

- A panel update arrives while the user is typing in its input block: the typed text and cursor survive (Task 2).
- A plugin that exits or is stopped with panels open: its panels close, its marks clear, and a pending pick or prompt is dismissed (Task 5).
- A pick or prompt arrives while another is open or the user is in insert mode: it waits in a queue and opens when dusk is back in normal mode (Task 4).
- Marks for rows past the end of the buffer, or for a file that is not open: ignored without error, applied when the file opens (Task 6).
- A very long list (10000 rows) or text block: drawing stays bounded to the visible rows (Task 3).

**Files:** Modify `src/host.rv`; Test `src/host_test.rv`; Modify `tests/fake-plugin/src/main.rv` (command `fake.panel` sends a panel with every block kind; `fake.pick` requests `ui/pick` with items a, b, c and reports the answer as message `picked <label>`; `fake.prompt` requests `ui/prompt` and reports `typed <text>`; `fake.marks` sends `marks/set` for the command's path with an error on row 0; `fake.close` sends `ui/close` for panel `p1`; every `ui/event` it receives is echoed as message `event <panel> <block> <kind> <value>`).

**Interfaces:**
- Produces in `host.rv`:
  - `class Block { id: str, kind: str, text: str, items: list[(str, str)], label: str, value: int }` (`value` -1 when absent)
  - `class PanelSpec { id: str, title: str, dock: str, blocks: list[Block] }`
  - `class Mark { row: int, severity: str, message: str, sign: str }`
  - New `HostAction` variants: `Panel(str, PanelSpec)`, `ClosePanel(str, str)`, `Pick(str, int, str, list[(str, str)])` (plugin, request id, title, items as label and detail), `Prompt(str, int, str, str)` (plugin, request id, title, initial), `Marks(str, str, list[Mark])` (plugin, path, marks).
  - `fun send_event(self, panel: str, block: str, kind: str, value: JsonValue)` sends `ui/event` `{"panel","block","kind","value"}`.
  - `action_text` covers the new variants: `panel:<id>:<n blocks>`, `close:<id>`, `pick:<title>:<n>`, `prompt:<title>`, `marks:<path>:<n>`.

### Task 2: Panel model and block layout

**Files:** Create `src/ui.rv`; Test `src/ui_test.rv`; Modify `rv.toml` (add `"github.com/martian56/magpie" = "v0.5.0"`).

**Interfaces:**
- Produces:
  - `class PanelState { owner: str, spec: PanelSpec, scroll: int, sel: dict[str, int], input: dict[str, str], cursor: dict[str, int], focus_block: int }`
  - `fun new_panel(owner: str, spec: PanelSpec) -> PanelState`
  - `fun replace_panel(old: PanelState, spec: PanelSpec) -> PanelState` (keeps scroll, selection when in range, input text and cursor when the new input block has empty `text`, focus block)
  - `class Row { text: str, kind: str, block: int, item: int }` where kind is `text`, `item`, `item_sel`, `input`, `button`, `button_sel`, `progress`, `title`
  - `fun layout(p: PanelState, w: int, tick: int) -> list[Row]` (text blocks through magpie `render` then `plain`, wrapped to `w`; list rows `label  detail`; the input block as its lines with a `> ` lead; buttons on one row as `[ label ]`; progress as `<spinner> label` or `label [#####-----] 50%`)
  - `fun panel_key(p: PanelState, name: str, text: str) -> (str, str, str)` returns an event to send as (block id, kind, value) or ("", "", "") for none; kinds `choose` (value: item index), `submit` (value: input text, then the input clears), `press` (value: button index).
